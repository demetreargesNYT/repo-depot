## Shared rooms and how the manifest records them

Rive transitions are AND-only, so "scene A and scene B are one room" is built by **twins**: for each base scene (`chapter-3`, `ad`, `chapter-4`, `end`), every transition that waits for `scene == base` (and `startScene == base`) in every state machine layer (the Backdrop colour poses, the room's layers, the city layers, the ball, the fireworks) gets a twin per sharing scene, and every transition that leaves on `scene != base` also requires `scene != each sharing scene`. A change between scenes of one group is a same-room change: nothing resets, nothing pans (measured frame for frame in throwaway runs). The Backdrop's Boot state also got self-cuts for the two badge scenes.
Manifest entries (`chapter.json` "scenes"): `kind: "shared-room"` + `sameRoomAs: "<base>"` and **no `room` key** (chapter-3-2, top-game, editor-video, share); `kind: "shared-picture"` + `sameRoomAs: "ad"` for the two badge scenes; `editor-video` also has `fireworks: "off"`. "poses" lists every scene that uses a colour pose; "tests.flow" lists the base scenes. `tools/check_chapter.py` understands shared rooms now (commit 49ee665); `npm run check ch3` passed 834 of 834 before the push.
To add another sharing scene: add its enum value, then extend `GROUPS` in `ch3_scene_names.py` logic -- but see "The engineering contract" below: **no new scenes any more**.
