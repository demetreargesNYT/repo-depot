Year in Games 2026 · Chapter 2 · For engineering

One Rive file, one number

Each chapter is one Rive file. It opens on the chapter's room, then moves through the player's games in their order. Engineering sets one number, Scene, on each tap: 0 for the opener, or the game the frame shows. When the game changes, the current room leaves and the next one arrives. When it doesn't, Rive keeps looping and only the page text changes. The preview runs the exact code shown further down, with only the Rive object stubbed.

    What engineering writes

    1. Load the chapter's file with autoplay on. That's the standard Rive setup.
    2. Set Scene on every tap to the scene the new frame shows, from the frame list they already build from the player's stats.
    3. Reveal the next copy with class yig-in, plus yig-quick when the scene didn't change. The CSS handles all the timing.
    chapter-2.js · the code running this preview
    
    
    No state machine logic, no Rive events, no animation timing in JavaScript. Setting Scene to the value it already has does nothing, so it's always safe to set it.

    Text motion CSS
    
    
    Drop-in, no JavaScript. Copy marked yig-in waits 3.2 seconds for the scene to change, then each line rises from behind its own mask. Add yig-quick when the scene stays the same, and it rises right after the old copy leaves. Copy marked yig-out lifts away.
    
    
    yig-text-motion.css
    
    
    /*
  Year in Games text motion, v2. CSS only, no JavaScript required.

  Two moves for page text, both on fixed timing:
    Rise in  - each line slides up from behind its own mask, top to bottom.
    Lift out - each line slides up and out, faster.
  An icon or image in the block uses Pop on the way in.

  How to use it:
    1. When the player taps, render the next frame's copy with class "yig-in".
       It waits --yig-delay (the length of the Rive transition), then rises in on its own.
    2. If the frame stays on the same game (no Rive transition), also add class "yig-quick":
       the copy then rises in right after the old copy leaves instead of waiting for the scene.
    3. Optional: give the old copy class "yig-out" and remove it 300ms later.
       If you simply swap the copy instead, the old text cuts out while the scene moves, which is fine.

  Markup, one .yig-mask per designed line:
    <div class="yig-text yig-in">
      <img class="yig-pop" src="wordle.svg" alt="Wordle">
      <span class="yig-mask"><span class="yig-line">On average, you solved</span></span>
      <span class="yig-mask"><span class="yig-line">Wordle puzzles in</span></span>
    </div>
  No time to split lines? Put the text straight into <div class="yig-text yig-in"> and the
  whole block rises as one piece.
*/
:root {
  --yig-delay: 3.2s;        /* Rive transition length. Shelf to Wordle: 3.2s */
  --yig-rise: 560ms;
  --yig-lift: 260ms;
  --yig-pop: 440ms;
  --yig-step: 70ms;         /* delay between lines on the way in */
  --yig-lift-step: 30ms;    /* delay between lines on the way out */
  --yig-ease-rise: cubic-bezier(0.16, 1, 0.3, 1);
  --yig-ease-lift: cubic-bezier(0.7, 0, 0.84, 0);
  --yig-ease-pop: cubic-bezier(0.34, 1.56, 0.64, 1);
}

.yig-text.yig-quick { --yig-delay: 300ms; } /* same scene: no Rive transition to wait for */

.yig-mask { display: block; overflow: hidden; padding-block: 0.08em 0.2em; margin-block: -0.08em -0.2em; }
.yig-line, .yig-pop { display: block; }

/* stagger order comes from position in the block, so no index attributes are needed */
.yig-text > :nth-child(1) { --yig-n: 0; } .yig-text > :nth-child(2) { --yig-n: 1; }
.yig-text > :nth-child(3) { --yig-n: 2; } .yig-text > :nth-child(4) { --yig-n: 3; }
.yig-text > :nth-child(5) { --yig-n: 4; } .yig-text > :nth-child(6) { --yig-n: 5; }
.yig-text > :nth-child(7) { --yig-n: 6; } .yig-text > :nth-child(8) { --yig-n: 7; }

.yig-in .yig-line {
  animation: yig-rise var(--yig-rise) var(--yig-ease-rise) both;
  animation-delay: calc(var(--yig-delay) + var(--yig-n, 0) * var(--yig-step));
}
.yig-in .yig-pop {
  animation: yig-pop var(--yig-pop) var(--yig-ease-pop) both;
  animation-delay: calc(var(--yig-delay) + var(--yig-n, 0) * var(--yig-step));
}
.yig-in:not(:has(.yig-mask, .yig-pop)) {
  animation: yig-rise-block var(--yig-rise) var(--yig-ease-rise) both;
  animation-delay: var(--yig-delay);
}
.yig-out .yig-line {
  animation: yig-lift var(--yig-lift) var(--yig-ease-lift) both;
  animation-delay: calc(var(--yig-n, 0) * var(--yig-lift-step));
}
.yig-out .yig-pop, .yig-out:not(:has(.yig-mask, .yig-pop)) {
  animation: yig-lift-block var(--yig-lift) var(--yig-ease-lift) both;
}

@keyframes yig-rise { from { transform: translateY(120%); } to { transform: none; } }
@keyframes yig-lift { to { transform: translateY(-120%); } }
@keyframes yig-pop { from { transform: scale(0.85); opacity: 0; } to { transform: none; opacity: 1; } }
@keyframes yig-rise-block { from { transform: translateY(0.6em); opacity: 0; } to { transform: none; opacity: 1; } }
@keyframes yig-lift-block { to { transform: translateY(-0.5em); opacity: 0; } }

@media (prefers-reduced-motion: reduce) {
  .yig-in .yig-line, .yig-in .yig-pop, .yig-in:not(:has(.yig-mask, .yig-pop)) { animation-name: yig-fade-in; animation-duration: 200ms; }
  .yig-out .yig-line, .yig-out .yig-pop, .yig-out:not(:has(.yig-mask, .yig-pop)) { animation-name: yig-fade-out; animation-duration: 200ms; }
}
@keyframes yig-fade-in { from { opacity: 0; } to { opacity: 1; } }
@keyframes yig-fade-out { to { opacity: 0; } }
